# Security policy

## Supported versions

Security fixes are currently made for version 0.1.0.

## Report a vulnerability

Do not attach sensitive build captures, credentials, or private repository
content to a public issue. Use the repository host's private vulnerability
reporting feature when it is available. If no private reporting channel is
shown, open a minimal public issue requesting private contact and include no
exploit details or sensitive data.

Include the affected version, operating system, impact, and the smallest safe
reproduction you can provide. The project does not promise a response time.

Before sharing a capture, remember that redaction is pattern-based and
best-effort. Review both the preview and the exported artifact. The current
review and residual risks, including imported SQLite databases, are documented
in [docs/security-review.md](docs/security-review.md).
