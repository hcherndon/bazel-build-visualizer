# ADR-002: Java 21 LTS as the language baseline

Status: **Superseded by [ADR-008](008-java-25.md)** (2026-08-21).
Originally accepted 2026-08.

> The baseline is now Java 25 LTS. The content below is preserved unchanged
> as the historical reasoning — it is why the project picked an LTS, why it
> relies on records, sealed types, and virtual threads, and why preview
> features are forbidden. That last constraint survives the supersession and
> is still binding. Only the version number moved; see ADR-008 for the move
> and its consequences.

## Context

The project needs a single language level for all fifteen modules, chosen for
longevity (this is a tool people install, not a service we redeploy), for the
concurrency model (many blocking capture/enrichment tasks), and for value
modeling (a large domain of small immutable data carriers).

## Decision

Target Java 21 LTS exactly. The toolchain is pinned in the `bbv.java-common`
convention plugin and auto-provisioned via the foojay resolver declared in
`settings.gradle.kts`, so contributors do not need a preinstalled JDK 21.

Features we rely on:

- **Records** for identifiers and value types (`SessionId`, synthetic fixture
  types, and the domain model to come).
- **Sealed interfaces + pattern-matching switch** for closed event/state
  hierarchies with compiler-checked exhaustiveness.
- **Virtual threads** for blocking capture, enrichment, and external-process
  work, keeping the executor inventory small (plan section 19).

Preview features are forbidden; nothing may require `--enable-preview`.

## Consequences

- No newer-JDK language features (no unnamed variables from 22+, no FFM
  beyond what 21 finalizes) until the baseline is deliberately raised.
- `jpackage` bundles a Java 21 runtime; the app never depends on a
  system-installed JVM at runtime.
- CI and local builds provision the same Temurin 21 toolchain, so "works on
  my machine" JDK drift is off the table.

## Revisit when

The next LTS (25) has been GA long enough that a bundled-runtime bump costs
nothing, or a concrete feature (e.g. finalized FFM improvements for the
mmap-heavy graph indexes) justifies moving early.
